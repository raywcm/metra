# 架构与采样

Metra 使用 Go、Bubble Tea v2、Bubbles v2、Lip Gloss v2 和 gopsutil v4。采集与绘制分开执行，平台差异集中在独立后端。

```text
cmd/metra           参数、信号、启动程序与非交互摘要
internal/tui      Bubble Tea 状态机、Bubbles 文本输入、Lip Gloss 布局
internal/collector gopsutil 采集、计数器差值、不可变快照
internal/chart    时间戳环形历史、1×2 深浅方块、折线与网格
internal/platform Linux/macOS 磁盘映射、GPU / NPU 后端与进程信号
internal/config   校验、加载、原子保存
internal/i18n     中英文 JSON 语言包、系统语言识别和回退
```

## 事件与生命周期

Bubble Tea 负责键盘事件、终端缩放、差异绘制和备用屏幕恢复；30 FPS 是绘制上限，采样默认 1 Hz。采集通过异步命令返回快照，主循环不等待系统 I/O。前一个采样结束后才安排下一个，减去本次采集耗时以尽量维持目标周期；慢采样不会积压定时任务。一次硬件采样的 context 限制为 5 秒，外部 GPU 命令还有 1.2 秒子限制；系统内核调用是否立即响应取消由底层 API 决定。

每次快照都包含 CPU、内存、磁盘与网络。进程列表仅在 Processes 页可见时采集，最多 1 Hz；详细命令、用户和状态仅在打开详情时查询。文件系统容量 15 秒更新一次。Linux 在包初始化时启用 gopsutil 的进程启动时间缓存，避免每次进程状态查询都重新扫描整机 `/proc/stat`，降低数百核、数千进程场景的开销。没有每进程采样 goroutine，不持续执行 `ps`、`top`、`iostat`。macOS 详情中的状态查询由 gopsutil 按需调用系统工具。

SIGINT / SIGTERM 取消程序 context，Bubble Tea 退出时恢复光标和备用屏幕。退出 metra 不结束被监控进程。确认框的 Enter 默认取消；只有 y 发送 SIGTERM。创建时间不可读、PID 已变化、PID ≤1 或 metra 自身均拒绝信号。传统 PID + 创建时间检查仍有很小的系统调用间竞态，不能提供 pidfd 式原子身份保证。

## 数值语义

- CPU 由两次累计时间差计算；总值取各逻辑核心平均，进程的 100% 代表一个核心。
- 磁盘和网络使用字节计数器差值 / 实际经过秒数。首次采样、计数器减少和无效时间间隔为 NaN，界面显示横线或省略相应字段。
- Linux 磁盘利用率为累计 I/O 忙碌毫秒差值 / 时间；不是硬件饱和度，受内核与驱动语义限制。macOS 不提供此值。
- 未知值以 NaN 或显式有效标志表示，隐藏不可用的硬件字段，表格以横线表示未读到的值。Linux 的 GPU 后端按驱动暴露的属性提供部分数据。
- macOS GPU 通过 purego 调用 IOKit / CoreFoundation，读取 IOAccelerator 的 PerformanceStatistics 实时利用率与统一内存，缺失驱动时才回退 system_profiler 识别。所有复制的 CF 对象、迭代器和 registry 对象均释放；不使用 sudo。NPU 独立匹配 ANE 服务，不能把 IOServiceBusyTime、电源状态或 GPU 活动冒充 NPU 利用率。
- 稳定设备 ID 与标签编号分离。设备数量变化时保留当前选中设备；设备消失时回到 Performance。磁盘仅取物理块设备；APFS 未映射卷单独展示。

## 图表与内存

每终端字符使用 1×2 方块子格，以 █ / ▀ / ▄ 表示占用，另一种浅色 █ 表示空余；不同序列保留各自颜色。图形高度按最接近的半字符子格四舍五入；不足半个子格的数值不着色，0% 不产生占用块，100% 填至顶部。原始读数和历史数据不因绘图取整而改变。网格默认关闭；标题和当前使用量位于边框外。百分比图内部固定 0–100%，网络按吞吐量自适应缩放；界面不显示固定“100%”和满量程标记。

横坐标按 Range / (Width - 1) 的固定绝对时间栅格计算，视窗只移动整数列。每个历史样本的列编号保持固定，Bresenham 连线和列包络填充只作水平平移，避免移动视窗时对每个端点重新取整造成旧线段上下跳变。绘图保留左边界外的前一个样本，完整线段栅格化后裁切；新样本只延长末端，不重画已有线段。缺失点、长间断和暂停空隙不连线。最多保留 1802 点 / 曲线，覆盖最短 500 ms 周期下的 15 分钟；没有历史文件和后台进程。

点阵绘制分支、设置选项和配置字段已移除，旧配置字段会在读取时忽略，不重置其他配置；保存时不再写出。CLI 仅为既有脚本兼容 `--chart-style blocks`。

每曲线的存储上限约为 58 KiB（Go `time.Time` + float64），再加绘图时的临时副本。CPU 核数和设备数决定总曲线数量；设备消失会释放对应历史。调整范围不会补出尚未采集的数据。暂停冻结采样及图表时间轴，恢复后保留实际时间空缺。

## 已知边界

不支持 Windows 主机；可以在 Windows Terminal 中通过 SSH 监控 Linux/macOS。硬件名称来自操作系统，虚拟设备可能与实物编号不同。Intel DRM 利用率等属性若驱动未暴露则 N/A；不附带厂商闭源驱动。终端需支持 UTF-8 方块字符。小窗口自动降为数值；长详情、核心数值表和多设备总览支持滚动。

## 语言与自动主题

界面文字通过 `internal/i18n` 的 en / zh-CN JSON 目录翻译，缺失条目回退英文。新增 UI 文案会由 AST 检查要求同时提供两种翻译，格式占位符也会校验。自动语言遵循 locale 环境变量；固定语言选择可保存在设置文件。

默认主题 auto 通过 Bubble Tea 的 `RequestBackgroundColor` / `BackgroundColorMsg` 读取终端实际背景，使用对应的文字、网格、填充与输入框配色。启动、聚焦和每 15 秒查询一次，不因暂停采样而停止主题检测。没有报告时使用 `COLORFGBG` 或深色回退。手动主题优先于检测值；强制主题会设置并在退出时恢复终端背景/前景。

磁盘单独记录 ReadTime / WriteTime 的服务时间差值；页面上图为整体占用率，下图为同一量程下的读、写速度双曲线。上图优先使用 Linux IoTime；macOS 则把读写服务时间加总并明确标注，显示上限 100%。并行或排队 I/O 的服务时间可能累加；该值不是磁盘物理带宽的百分比。macOS 的 gopsutil IoTime 是读写时间相加，不作为 Linux 同语义的总活跃时间。驱动不提供时间计数器时显示 N/A。

## 设置与内存组成

设置使用草稿编辑：普通态左右切页、Enter / 上下键进入编辑；编辑态上下选项、左右 / 空格修改草稿、Enter 原子保存、Esc / q 取消，Tab 切页丢弃草稿。草稿可预览语言、主题和采样参数，保存失败时保持草稿。顶部一行显示对应操作提示，字段逐行紧凑排列，构建版本号作为只读项，不写入用户配置以免升级后过期。

内存已用定义为 Total - Available，组成横条展示使用中、已修改、可回收和空闲，总宽度代表当前可见的内存总量。可回收为 Available - min(Free, Available)，已修改取 Linux Dirty 并从使用中分出；macOS 未提供的已修改指标省略。横条统一使用强调色占用块与浅色空余块。

## 有效资源与服务器界面

`internal/platform/resources*.go` 将亲和性、cgroup 挂载根 / 成员关系、cpuset、CPU quota、内存限制、层级余量与 Slurm 分配转换为可见资源上限。CPU quota 保留小数，按 `cpu.stat` / `cpuacct.usage` 差值归一化；不使用 `GOMAXPROCS` 作资源额度。内存工作集扣除 `inactive_file`，各级余量结合可回收缓存后再与主机可用量取最小值。缺失的作业使用计数器保持未知；权限不足记录实际读取错误。RLIMIT_AS / RLIMIT_DATA 属于虚拟映射 / 数据段约束，不修改物理内存总量。

CPU 页面在可运行核心数量 ≥64 时只生成数值表，不保留每核心历史，避免 192 核等机器的图表与分配开销；配额只限制 CPU 时间而未绑定 cpuset 时，仍会列出真实可运行的 CPU ID，不任意虚构几个“专属核心”；CPU ID 保留实际亲和性映射。所有操作提示位于第一行。GPU 显存横条使用设备容量，统一内存则明确引用整机系统 RAM 池，和当前 CPU / RAM 分组配额分开。

## 加速器引擎与频率

`platform.Engine` 为每个实际可读引擎分配稳定 ID，GPU / NPU 分别保存独立历史。页面根据终端宽度采用单列或双列小图，保持 0–100% 同一量程和深浅方块；数据多时沿用硬件页滚动。显存控制器 / HBM 带宽使用率与设备内存容量条分别显示。

NVIDIA 后端在初次采集时检查驱动的 `--help-query-gpu`，在基本 CSV 字段之外加入支持的引擎和频率字段。缺失属性保持未知；扩展查询不兼容时回退基本查询。AMD 可读取 `pp_dpm_sclk` / `pp_dpm_mclk` 当前标记值，Intel 在接口可见时读取 `gt_cur_freq_mhz`。DRM 设备先过滤 VirtIO / QXL / Bochs / Hyper-V 和 AST / Matrox 管理显示适配器；NVML 工具可用时由其统一枚举 NVIDIA，避免重复 DRM 标签。

昇腾后端读取 `npu-smi info` 的真实可见卡 / 芯片编号和 HBM 容量，再以最多四个工作协程查询 `info -t usages` 的 AI Core、AI Vector、AI CPU、控制 CPU 和 HBM 带宽。每个附加查询限制 1.2 秒。驱动的 common / driver 库目录只加入子进程环境，不修改 metra、自身 shell 或系统动态链接配置。采集失败保留已知设备及引擎身份，曲线留下空缺，不填成零或临时撤掉图框。

Linux CPU 频率按实际可运行 CPU ID 与 cpufreq policy 求交，读取当前频率、按关联 CPU 数加权平均，并记录最小 / 最大值。cpufreq 不可用时读取 `/proc/cpuinfo` 的 `cpu MHz`，不使用 BogoMIPS 估算。macOS 只在系统接口报告频率时显示并标明来源。频率放在 CPU 页面头部，不受大核数表格模式影响。

GPU / NPU 的总体百分比通过 `PeakUtilization` 取各可读引擎中的最大值；NVIDIA 的 GPU / 计算、Ascend 的 AI Core 本身也作为独立引擎保留，避免将峰值误写成某个单独引擎的使用率。总体指标用于总览与总体历史，详细页展示各单元自己的曲线。页面去除配额 / 共享主机 / 主机总量说明，底层归一化与内存上限仍按有效分配计算。

## PCIe 与设备内存带宽

Linux NVIDIA 后端通过 purego 动态读取现有驱动的 NVML，无需编译链接或额外安装运行库。PCIe 接收 / 发送计数器从 KiB/s 转为字节速率；两方向分别除以链路单向编码带宽，保留独立占用率，不相加。量程根据驱动报告的最高 PCIe 代际与当前链路宽度计算；未知代际只显示速率，不猜占用率。

支持 GPM 的 GPU 使用前后两个采样读取 DRAM 带宽指标，相对于设备理论带宽上限。H100 / H200 / A100 标为 HBM 带宽，其他支持设备标为显存带宽；它与显存控制器忙碌时间、显存容量占用分别保留。采样沿用正常刷新周期，不等待额外窗口，不启用 GPM streaming、不修改驱动设置；退出时释放采样缓冲区和 NVML 句柄。

编码与解码共享一张双曲线图；显存控制器与 HBM / 显存带宽共享一张双曲线图；PCIe 接收与发送共享一张图，并在框外显示速率和可读的占用率。窄终端的两条图例会换行，保持两方向都可见。

## 图层与引擎能力

多序列图按图例顺序分配前景优先级：接收 / 读取、显存控制器位于前景，较小的发送 / 写入或 HBM 填充不会覆盖前景颜色；第二序列高于第一序列的部分仍可见。图例名称前显示同色标记。

NVIDIA 通过只读 NVML 属性查询分配设备的媒体引擎数量；物理设备可使用整卡 MIG profile 的引擎计数，无需启用 MIG。引擎数量为零或 API 明确不支持时隐藏，并从历史身份保留中排除；存在但空闲的引擎保留 0%。已知引擎临时采样失败仍显示缺失点，不误判为硬件不存在。旧驱动未暴露能力时保留可读的接口数据，不仅凭 0% 推断不存在。

## 空间预算与 CPU 温度

`metricPanel` 将图形、图例、数值与优先级放在同一个布局描述中。规划器先保留全部数值，在完整边框（至少 4 行）和图例可放入时才选择图形；次要图形降为数值后再尝试。每行的列宽与图高都分配整数除法的余量，末行按实际列数扩展至全宽。硬件正常图形视图填满内容区；数值过多时只滚动数值，不裁切图框。常规屏幕的内容区为终端高度减 5，小窗口减少分隔线；最终视图逐行填充到准确宽高。进程表按实际可用行数显示，光标分页使用相同预算。

CPU 温度每 2 秒采集。Linux 的 gopsutil sensors 读取 hwmon / thermal；只接收明确 CPU 驱动或 CPU 名称的传感器，过滤 GPU、存储、电池、PMU 与无效值。macOS 优先读可识别的 CPU HID / Intel SMC；Apple Silicon 的 HID 仅报告 PMU 时，用 purego 调用 AppleSMC 的只读 key info / read 操作，读取 CPU 专属键的 float32 / sp78 温度。无需 sudo、不写 SMC、不调风扇；连接与服务句柄在每次采样结束释放。温度汇总取已确认 CPU 传感器的最高值。驱动没有暴露、权限不足或本次读取失败时不伪造温度。

显存条已有最接近整数宽度的取整。内存组成改为各累计边界四舍五入，避免逐段截断造成的累计偏差，空余部分补足全宽；不足半格的小段若恰好跨过累计取整边界，会合并到相邻可见段，避免制造彩色细条。图表超过 25 万字符的绘制预算时退为数值，保持资源开销有界。

## 数值热度背景

图形与数值使用独立的 `labels` / `numericLabels`，依布局结果选择；不从显示文案反推数值，背景不改变原始读数或列宽。数值占用率按硬件强调色与当前主题的空余底色插值，使用开方曲线增强低负载的可辨识度；0.0% 使用中性底色，未知 / 非法值无热度背景。黑白前景按 sRGB 相对亮度选择较高对比度。CPU 大核数表和极小窗口同样使用此规则；缺少已知容量 / 链路分母的速率不生成热度。

## 进程顺序与有用设备

进程默认 CPU 降序，CPU 以界面的一位小数精度分桶，再按已知 RSS 降序、PID 升序。内存排序同样使用 CPU 作为次排序；反向不把未知字段推到前面。初始与自动刷新跟随榜首，只有人工导航才锁定 PID / 创建时间，并尽量保持选中行在屏幕上的位置；排序、清除搜索和 Home 退出锁定，已退出或复用的 PID 不沿用选择。进程树保持父子关系，仅对同级排序，不将子进程资源重复汇总。

文件系统在调用 Usage 前过滤 Snap / squashfs、系统伪挂载、boot / EFI、非根 overlay，以及容器挂入的 hosts / hostname / resolv.conf；同设备与文件系统的重复 bind 只保留一份容量，优先根目录。根 overlay 和只读数据文件系统仍保留，APFS Data 与真实数据盘 / 网络存储不因只读而被排除。Linux 的 /dev/mapper 链接会解析到实际 dm 设备后再关联。

网络先按管理状态、地址和已知内部名称过滤；默认路由可以保留容器中唯一的 veth 出口，地址正常的 bond / VLAN / VPN 不会仅因虚拟类型被丢弃。Linux 默认路由每 15 秒读取 proc IPv4 / IPv6 表，列表优先显示默认接口；人工选择按名称跨刷新保留。底层 VPN 与物理接口同时可见时，仅物理层进入总览汇总，VPN 详情仍展示自身计数器；仅有隧道时则使用隧道作为汇总。过滤掉的接口不再保留采样缓存。
